# cs2cinema

## What This Is

cs2cinema — десктопное приложение для Windows (Rust, egui) и CLI `cs2-cli`, которые из демки CS2 (локальный `.dem` или матч FACEIT по ссылке) автоматически делают видеомонтаж: парсят демку, находят моменты игрока, планируют камеры, записывают дубли через HLAE в реальном CS2 и склеивают ролик через ffmpeg. Пользователь один — автор, на своём ПК, со своим CS2 и HLAE.

Этот этап («Надёжность записи») про то, чтобы задача из очереди либо доходила от ссылки FACEIT до `highlights.mp4` без ручного вмешательства, либо быстро падала с понятной причиной.

## Core Value

Задача на монтаж из очереди доходит до готового `highlights.mp4` без ручного вмешательства, а если это невозможно — останавливается быстро и объясняет, что именно пошло не так.

### Active

<!-- Гипотезы этого этапа. Подтверждаются прогоном 5 матчей подряд. -->

- [ ] Перед запуском записи приложение проверяет окружение (Steam запущен, CS2 не запущен другим процессом, пути HLAE и CS2 существуют и содержат нужные файлы, совместимость HLAE с текущей версией CS2, `ffmpeg`/`ffprobe` доступны, есть место на диске) и не начинает запись, если проверка не прошла, а показывает, что именно не так
- [ ] Каждая точка отказа при старте игры отличима в журнале задачи и в тексте ошибки: процесс CS2/HLAE не поднялся; игра поднялась, но демка не загрузилась (`playdemo`); демка загрузилась, но `cs2c_NN.cfg`/campath не исполнились; маркер начала/конца дубля не пришёл
- [ ] Запись не виснет: каждое ожидание (старт процесса, загрузка демки, консольный порт, дубль) ограничено таймаутом, по таймауту задача падает с указанием этапа и последних строк журнала, а не ждёт бесконечно; ошибка опроса процесса не трактуется как «игра жива»
- [ ] Отмена задачи срабатывает за секунды на любом этапе, включая ожидание внешних процессов, и приводит систему в чистое состояние (игра закрыта, временные файлы помечены)
- [ ] Приложение управляет только тем процессом CS2, который само запустило (по PID/дескриптору), а не убивает все `cs2.exe`
- [ ] Дубли находятся по явным признакам (ожидаемые имена/номера, маркер завершения), а не по времени изменения папки; каждый дубль проверяется `ffprobe` до сборки, и неполный дубль даёт понятную ошибку с номером дубля
- [ ] Упавшую или отменённую задачу можно повторить с этапа записи без повторного скачивания и планирования; задачи, прерванные падением приложения, после перезапуска возобновляются или честно помечаются с причиной
- [ ] Этапы записи и сборки вынесены в `pipeline` за `Progress`, внешние процессы (HLAE, CS2, ffmpeg, tasklist) спрятаны за трейтом с фейковой реализацией, и сценарии «не стартует», «таймаут», «отмена» покрыты автотестами без CS2
- [ ] Контрольный прогон: 5 разных матчей FACEIT (разные карты) поставлены в очередь и все доходят до `highlights.mp4` без ручных действий

### Out of Scope

- Публичный релиз, установщик, английский интерфейс — пользователь один, своя машина; это другой этап
- Улучшение режиссуры и качества монтажа — текущий diff с режиссурой коммитится как база, дальше качество не трогаем, пока не стабильна запись
- Надёжность `cs2-cli` как отдельная цель — CLI не должен сломаться и должен собираться, но критерий «5 подряд» относится к приложению
- Linux/macOS — HLAE и запись CS2 работают только на Windows
- Потоковая обработка длинных демок и экономия памяти — не связано с зависанием записи
- Падения парсера на экзотических демках (fuzzing `crates/demo`) — не главная боль сейчас; если всплывёт в прогоне, добавим как точечную правку

## Context

- Карта кодовой базы: `.planning/codebase/` (ARCHITECTURE.md, STRUCTURE.md, CONCERNS.md, TESTING.md и др.), снята с коммита `469e893` 2026-10-10.
- Текущее состояние записи: `crates/app/src/launch.rs` ищет и запускает `HLAE.exe`, опрашивает `tasklist` раз в секунду (`game_alive` при ошибке опроса возвращает `true`), ждёт дубли по времени изменения папки и «стабильности N секунд», убивает игру через `taskkill /IM cs2.exe /F`. Последовательность запись → сборка живёт в `crates/app/src/jobs.rs`, а не в `crates/pipeline`; CLI дублирует её своим путём.
- Типичный сбой по словам пользователя: «игра не стартует», причины разные (окружение, демка не грузится, конфиги не подхватываются), и в момент сбоя непонятно, какая именно. Отсюда приоритет на диагностику и предпроверки, а не только на исправление одного бага.
- В рабочей копии на момент инициализации был незакоммиченный diff (~2500 строк: director, renderer, app, README) — это завершённая работа по режиссуре и карточкам задач, коммитится как база этапа.
- Тесты: `cargo test --workspace`; реальные демки через `CS2_TEST_DEMO`; ffgraph можно проверить без CS2 через «пустые» дубли и `assemble.bat` (см. память проекта).
- Интерфейс, журнал задач и сообщения об ошибках — на русском языке; идентификаторы в коде — на английском.
- Внешние зависимости: HLAE (`x64\AfxHookSource2.dll`), CS2 через Steam, `ffmpeg`/`ffprobe` в PATH, карты из awpy-data через `git ls-remote`, FACEIT Data API по ключу.

## Constraints

- **Tech stack**: Rust cargo workspace, egui/eframe, `std::thread` без tokio, SQLite через rusqlite — не менять стек, встраиваться в существующие крейты
- **Platform**: только Windows — HLAE и запись CS2 нигде больше не работают
- **External tools**: HLAE и CS2 — внешние процессы с недокументированными маркерами консоли и структурой папок; любой детектор должен иметь таймаут и диагностику
- **Concurrency**: одна задача записи за раз — CS2 пишет только один экземпляр
- **Compatibility**: CLI `cs2-cli` должен продолжать собираться и проходить `crates/cli/tests/pipeline.rs`
- **Language**: пользовательские строки на русском
