# Requirements: cs2cinema — Надёжность записи

**Defined:** 2026-10-10
**Core Value:** Задача на монтаж из очереди доходит до готового `highlights.mp4` без ручного вмешательства, а если это невозможно — останавливается быстро и объясняет, что именно пошло не так.

## v1 Requirements

Требования этого этапа. Каждое привязывается к фазе роадмапа.

### Предпроверка (PRE)

- [ ] **PRE-01**: Перед записью пользователь видит единый отчёт предпроверки: список проверок со статусом ok/warn/fail, сообщением по-русски и подсказкой, как починить
- [ ] **PRE-02**: Предпроверка для задач с записью выполняется первой, до скачивания демки, парсинга и планирования; задачи «только план» её пропускают
- [x] **PRE-03**: Проверяются инструменты: `HLAE.exe`, `x64\AfxHookSource2.dll`, `cs2.exe` существуют; `ffmpeg` и `ffprobe` (и ffmpeg из `ffmpeg.ini` HLAE) запускаются и отвечают на `-version` в пределах таймаута
- [x] **PRE-04**: Проверяется, что Steam запущен (по снимку процессов, не по тексту `tasklist`)
- [x] **PRE-05**: Если запущен чужой `cs2.exe`, задача не стартует и сообщает об этом; чужой процесс никогда не убивается
- [x] **PRE-06**: Проверяется свободное место на диске результатов и на диске CS2 с оценкой объёма по плану
- [x] **PRE-07**: Проверяются входные данные и пути: демка существует и не является LFS-указателем, выходной путь без пробелов и доступен для записи

### Диагностика запуска (LCH)

- [x] **LCH-01**: Этап записи реализован как явная машина состояний с именованными состояниями (предпроверка → запуск лаунчера → ожидание процесса игры → консоль → демка готова → скрипт запущен → дубль N → закрытие → проверено) и явными состояниями сбоя
- [x] **LCH-02**: Любой сбой записи — типизированная ошибка с кодом, состоянием, сообщением по-русски, подсказкой и последними строками консоли; пользователь видит её в карточке задачи
- [x] **LCH-03**: Отсутствие маркера готовности (`READY`, `SCRIPT`, `TAKE_START`, `TAKE_END`) в срок — ошибка с соответствующим кодом, а не предупреждение с продолжением
- [x] **LCH-04**: Консоль игры (netcon и/или `console.log`) и stdout/stderr HLAE пишутся в кольцевой буфер и сбрасываются в `record.log` в папке задачи при любом исходе
- [x] **LCH-05**: При таймауте фазы запуска приложение определяет модальное окно ошибки HLAE/AfxHookSource2 и заголовки окон процессов игры и включает их в ошибку; первая строка `AFXERROR` в консоли завершает задачу сразу
- [x] **LCH-06**: Завершение лаунчера `HLAE.exe` и завершение игры `cs2.exe` различаются: код выхода лаунчера и живость игры — отдельные факты в журнале и ошибке

### Таймауты и отмена (TMO)

- [x] **TMO-01**: Каждое ожидание (запуск лаунчера, появление игры, консоль, загрузка демки, первый дубль, каждый дубль, закрытие игры, ffprobe, ffmpeg) имеет именованный дедлайн; по истечении задача падает с указанием этапа и прошедшего времени
- [x] **TMO-02**: Живость игры определяется по дескриптору процесса (ожидание на handle), а не опросом `tasklist`; ошибка проверки означает «неизвестно», а не «жива»
- [ ] **TMO-03**: Отмена переводит задачу в «отменяется» не более чем за 3 секунды и в чистое состояние не более чем за ~10 секунд в любом состоянии, включая ожидание внешних процессов; ни один вызов `Command::output()` без дедлайна на пути записи не остаётся
- [x] **TMO-04**: Игра завершается поэтапно: консольный `quit` → ожидание ~5 с → завершение своего процесса или Job Object → проверка, что процесс ушёл → короткая пауза
- [x] **TMO-05**: Приложение управляет только теми `cs2.exe` и `HLAE.exe`, которые само запустило: через Windows Job Object с `KILL_ON_JOB_CLOSE`, с запасным вариантом по (PID, время создания); `taskkill /IM` не используется
- [ ] **TMO-06**: При отмене или сбое игра закрыта, частичные дубли помечены (не удалены), установленные `cs2c_*.cfg`/`highlights.cfg` и копия демки обработаны по политике уборки
- [x] **TMO-07**: Следующая задача стартует только после подтверждения, что предыдущий `cs2.exe` завершён, и короткой паузы

### Дубли (TAK)

- [x] **TAK-01**: Ожидаемый набор дублей (`take0000..take{N-1}`, каждый с `video.mp4` и `audio.wav`) выводится из плана до начала записи
- [ ] **TAK-02**: Завершение каждого дубля определяется по явному консольному маркеру `TAKE_END n` (с nonce задачи) и завершению дочернего ffmpeg HLAE; стабильность размера файла — только вторичный признак; поиск по времени изменения папки не используется
- [ ] **TAK-03**: Для каждой попытки записи ведётся манифест дублей (`clips/manifest.json`): ожидаемая длительность, статус (pending/recorded/validated/invalid), размеры, измеренная длительность, хеш плана, разрешение, сборка CS2 и версия HLAE
- [ ] **TAK-04**: Каждый дубль проверяется `ffprobe` до сборки: есть видео- и аудиопоток, длительность > 0 и в допуске от плановой, разрешение совпадает; невалидный дубль даёт ошибку с номером дубля
- [ ] **TAK-05**: Файл дубля не читается, пока HLAE может его дописывать; «уже записано» означает «валидирован по манифесту», а не «файл существует»
- [ ] **TAK-06**: Итоговый `highlights.mp4` пишется во временное имя и переименовывается только после успешного завершения ffmpeg

### Повтор и восстановление (RET)

- [ ] **RET-01**: На задаче сохраняются этап сбоя, код ошибки и номер попытки; журнал не стирается между попытками, попытки разделены маркерами
- [ ] **RET-02**: Кнопка «Повторить» запускает задачу с этапа записи без повторного скачивания и планирования (план и входы хранятся в `record.json` в папке задачи)
- [ ] **RET-03**: Если все дубли валидированы, повтор начинается с этапа сборки, запись не повторяется
- [ ] **RET-04**: При запуске приложения осиротевшая игра, запущенная прошлым экземпляром (по сохранённым PID и времени создания), завершается; задачи в статусе «выполняется» помечаются «прервано» с достигнутым этапом и причиной, а не общим «ошибка»
- [ ] **RET-05**: Сбой одной задачи не останавливает очередь: следующие задачи выполняются, очередь завершается сама
- [ ] **RET-06**: Повтор не затирает улики: дубли и `record.log` предыдущих попыток сохраняются (`clips_old_<ts>`, `record.log.N`)

### Наблюдаемость (OBS)

- [ ] **OBS-01**: Журнал задачи ведётся с метками времени, этапа и попытки и сохраняется инкрементально; по нему видно длительность каждого этапа
- [ ] **OBS-02**: Карточка упавшей задачи показывает код, состояние, сообщение, подсказку, хвост консоли и кнопки «Повторить» и «Открыть папку»
- [ ] **OBS-03**: Для каждой задачи сохраняется снимок окружения (сборка CS2 из `steam.inf`, версия HLAE, версия ffmpeg, наличие NVENC, свободное место, разрешение) в папке задачи и в манифесте
- [ ] **OBS-04**: По завершении очереди уведомление в трее показывает итог: N готово / M упало, с первой причиной сбоя

### Тестируемость (TST)

- [x] **TST-01**: Внешние процессы (запуск, список, завершение, ожидание), консоль и часы спрятаны за трейтом `Host` с реальной Windows-реализацией и фейком в памяти; на не-Windows есть заглушка для CI. Файловая система за `Host` не прячется (решение D-03 фазы 1): машина записи работает с реальными путями, фейк в тестах пишет во временную папку
- [ ] **TST-02**: Сценарии «лаунчер не стартовал», «игра не появилась», «окно ошибки HLAE», «консоль не открылась», «демка не загрузилась», «скрипт не запустился», «маркер дубля не пришёл», «дубль обрезан», «игра умерла посреди дубля», «отмена в каждом состоянии» покрыты автотестами на фейке без CS2
- [ ] **TST-03**: Этапы записи и сборки принадлежат крейту `pipeline` за трейтом `Progress`; приложение и `cs2-cli` вызывают один и тот же код

### Приёмка (ACC)

- [ ] **ACC-01**: Фиксированный приёмочный набор из 5 матчей FACEIT на 5 разных картах хранится как список ссылок и ставится в очередь одним действием
- [ ] **ACC-02**: Критерии приёмки проверяются машинно: все 5 задач в статусе «готово», каждый `highlights.mp4` проходит `ffprobe` (видео + аудио, длительность в допуске от плана), `cs2.exe` не остался, ручных действий не было, число авто-повторов указано отдельно; прогон выполняется дважды — с перезапуском приложения между сериями и без
- [ ] **ACC-03**: Перед приёмкой один раз вручную проводятся учения: отмена в каждом состоянии, убить приложение посреди записи и перезапустить, завершить `cs2.exe` из диспетчера посреди дубля, старт при запущенном чужом CS2, временно убрать ffmpeg из PATH

### Дифференциаторы (DIF)

- [x] **DIF-01**: Приложение помнит пару (сборка CS2, версия HLAE) последней удачной записи и предупреждает в предпроверке, если сборка CS2 изменилась с тех пор
- [x] **DIF-02**: Предпроверка не даёт стартовать, пока Steam обновляет CS2 (по состоянию `appmanifest_730.acf`)
- [ ] **DIF-03**: После 2 подряд сбоев с одинаковым кодом класса «окружение» очередь встаёт на паузу с объяснением, а не прожигает оставшиеся задачи
- [ ] **DIF-04**: Для сбоев класса «запуск» (игра не появилась, консоль не открылась, демка не загрузилась, игра умерла рано) выполняется один автоматический повтор после полной уборки и паузы; авто-повторы считаются отдельно в журнале и приёмке

## v2 Requirements

Отложено. Отслеживается, но не входит в текущий роадмап.

### Дифференциаторы (DIF)

- **DIF-05**: Перезапись только отсутствующих или невалидных дублей (частичное возобновление)
- **DIF-06**: Таймауты по прогрессу («нет новых строк консоли и роста файла N секунд») в дополнение к абсолютным
- **DIF-07**: Адаптивные таймауты по истории (p95 загрузки демки и дубля × запас)
- **DIF-08**: Скриншот окна игры при сбое
- **DIF-09**: Кнопка «Скопировать диагностику» (ошибка, состояние, хвост консоли, снимок окружения)
- **DIF-10**: Пауза очереди после текущей задачи
- **DIF-11**: История попыток задачи в UI

## Out of Scope

Явно исключено. Документировано, чтобы не расползался объём.

| Feature | Reason |
|---------|--------|
| Публичный релиз, установщик, английский интерфейс | Пользователь один, своя машина; другой этап |
| Улучшение режиссуры и качества монтажа | Монтаж работает; diff с режиссурой закоммичен как база |
| Надёжность `cs2-cli` как отдельная цель | CLI должен собираться и проходить свои тесты, но критерий «5 подряд» относится к приложению |
| Linux/macOS | HLAE и запись CS2 только на Windows |
| Потоковая обработка длинных демок, экономия памяти | Не связано с зависанием записи |
| Fuzzing парсера демок | Не главная боль; точечно, если всплывёт в прогоне |
| Универсальная абстракция хоста под другие инжекторы/игры | Один хост (HLAE); трейт нужен для тестов, не для расширяемости |
| Распределённый рендер на нескольких машинах | Один ПК, одна игра |
| Отмена скачивания FACEIT посреди загрузки (`ureq` без cancel) | Принимается на этом этапе: отмена срабатывает на границе следующего этапа |
| Автоматическое убийство чужого `cs2.exe` | Противоречит требованию PRE-05 |
| Убийство по имени образа (`taskkill /IM`), опрос `tasklist`, поиск дублей по mtime | Исследование признало антипаттернами; заменяются TMO-02/05, TAK-02 |
| Переход на tokio/async | Существующий код на `std::thread`, не нужно для задач этапа |
