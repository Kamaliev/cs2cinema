# Requirements: cs2cinema — Сервер и Telegram-бот

**Defined:** 2026-10-11
**Milestone:** v1.1
**Core Value:** Задача на монтаж доходит до готового `highlights.mp4` без ручного вмешательства, а если это невозможно — останавливается быстро и объясняет, что именно пошло не так. Для v1.1: от демки, отправленной боту, до ролика в чате.

Требования v1.0 «Надёжность записи» заархивированы в `.planning/milestones/v1.0-REQUIREMENTS.md`.

## v1.1 Requirements

### Сервер и протокол (SRV)

- [x] **SRV-01**: Сервер запускается отдельной программой `cs2-server` на Linux, настройки берёт из файла и переменных окружения
- [x] **SRV-02**: Сервер хранит пользователей, задачи, раннеров и файлы в своей SQLite с миграциями
- [x] **SRV-03**: Задача проходит состояния receiving → queued → assigned → running → uploading → done / failed / cancelled; переходы проверяются тестом с виртуальными часами
- [x] **SRV-04**: Задача выдаётся раннеру атомарно с эпохой аренды; потеря аренды возвращает задачу в очередь, не останавливая запись на раннере
- [x] **SRV-05**: Раннер входит по токену (на сервере хранится только хеш), токен можно отозвать
- [x] **SRV-06**: Демка и результат передаются кусками по 8 МиБ с докачкой и проверкой размера и SHA-256
- [x] **SRV-07**: Число повторных выдач одной задачи ограничено (защита от цикла падений на «ядовитой» демке)
- [x] **SRV-08**: Команда `cs2-server submit` ставит задачу без Telegram, для тестов и отладки

### Бот (BOT)

- [ ] **BOT-01**: Бот отвечает только пользователям из белого списка; незнакомцу показывает его Telegram-ID; проверка идёт до `getFile`
- [ ] **BOT-02**: Админ управляет списком: `/adduser`, `/removeuser`, `/users`
- [ ] **BOT-03**: `/start`, `/help`, `/player` (ник или SteamID64); игрок фиксируется в задаче при постановке
- [ ] **BOT-04**: Демка файлом (`.dem`, `.dem.zst`) принимается после проверки магических байтов и размера, бот сразу подтверждает приём
- [ ] **BOT-05**: Ссылка FACEIT принимается со строгой проверкой; скачивание делает раннер, ключ FACEIT остаётся у автора
- [ ] **BOT-06**: Позиция в очереди, `/status`, `/queue`, одно сообщение статуса правится с ограничением частоты; бот сообщает, что раннер офлайн
- [ ] **BOT-07**: Готовый ролик приходит отдельным новым сообщением; при неясном итоге отправки задача получает состояние `uncertain` и команду `/resend`
- [ ] **BOT-08**: `/cancel` и `/retry`; повтор идёт по сохранённой демке без повторной загрузки
- [ ] **BOT-09**: Двухуровневый отчёт о сбое: другу — понятный текст без локальных путей; админу — код, этап, подсказка, число попыток
- [ ] **BOT-10**: Одна присланная демка — несколько задач (по игрокам), дубли определяются по хешу
- [ ] **BOT-11**: Лимиты на пользователя: число активных задач и размер файла

### Раннер (RUN)

- [ ] **RUN-01**: `cs2-cli runner` подключается к серверу сам, держит heartbeat, берёт задачу, скачивает демку, выполняет `run_job`, загружает результат
- [ ] **RUN-02**: Результат лежит в outbox, пока сервер не подтвердит размер и SHA-256; после перезапуска докачка идёт сама
- [ ] **RUN-03**: Этап и «дубль k из n» уходят на сервер; отмена с сервера доходит до пайплайна за секунды
- [ ] **RUN-04**: Сбои класса «окружение» возвращают задачу в очередь, а не роняют задачу друга
- [ ] **RUN-05**: Новые коды сбоев: `PLAYER_NOT_FOUND`, `PLAYER_AMBIGUOUS`, `NO_HIGHLIGHTS`, `BAD_DEMO`, `DEMO_TOO_LARGE`
- [ ] **RUN-06**: Перед загрузкой результат проверяется ffprobe (H.264, yuv420p, faststart), иначе Telegram не покажет видео

### Режим раннера в приложении (APP)

- [ ] **APP-01**: В настройках приложения задаются адрес сервера и токен; удалённая задача — обычная карточка очереди
- [ ] **APP-02**: Удалённая задача берётся только когда локальная очередь свободна и не на паузе
- [ ] **APP-03**: После перезапуска прерванная удалённая задача возобновляется сама
- [ ] **APP-04**: Приложение без сервера работает как раньше, `crates/cli/tests/pipeline.rs` остаётся зелёным

### Безопасность входа (SEC) — до приёма первой чужой демки

- [ ] **SEC-01**: Текст из демки (ники, карта) очищается от управляющих символов и не попадает в cfg; `drawtext` читает текст из файла; тесты на враждебных никах
- [ ] **SEC-02**: Лимит размера файла и распаковки, проверка магии, разбор в дочернем процессе с лимитом памяти
- [ ] **SEC-03**: `find_player` принимает точное или единственное совпадение; иначе `PLAYER_AMBIGUOUS` со списком до 10 кандидатов ещё до запуска CS2
- [x] **SEC-04**: Токены бота и раннеров не попадают в журналы и сообщения; тест с подставным токеном

### Эксплуатация (OPS)

- [ ] **OPS-01**: Уборщик чистит демки, результаты, `.part`, рабочую папку bot-api и сырые дубли на раннере
- [ ] **OPS-02**: Документация развёртывания: compose для `telegram-bot-api`, systemd-юнит, Tailscale или Caddy, резервные копии
- [ ] **OPS-03**: Сквозной тест с фейковым Telegram и `FakeHost`; сборка сервера на Linux в CI
- [ ] **OPS-04**: Учения: убить раннер посреди записи, обрыв загрузки, перезапуск сервера, отмена при офлайн-раннере, 500 МБ через прокси, несовпадение версий

## Out of Scope

| Feature | Reason |
|---------|--------|
| Публичный открытый бот, регистрация, тарифы | Доступ только по белому списку автора и друзей |
| Групповые чаты | Лимиты Telegram на сообщения, лишняя сложность; только личные чаты |
| Ключ FACEIT на сервере | Ключ остаётся у автора, скачивание делает раннер |
| Парсинг и запись на сервере | Запись возможна только на Windows-раннере с CS2 |
| Настройка монтажа из чата | Качество монтажа не меняем, пока цепочка не стабильна |
| Долги v1.0: приёмка на 5 матчах (04-12), учения D1–D6, проверка трея, живая проверка фикса дубля | Остаются в архиве v1.0 по решению автора; первый сквозной прогон RUN-01 станет живой проверкой записи |
