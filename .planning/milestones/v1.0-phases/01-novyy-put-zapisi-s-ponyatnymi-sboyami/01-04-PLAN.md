## Phase Goal

**As a** автор роликов, запускающий очередь задач на своём ПК, **I want to** чтобы задача с записью шла через новый `pipeline::record` поверх трейта `Host` и при любом сбое старта игры останавливалась в срок с типизированной ошибкой в карточке и в `record.log`, **so that** очередь не висит бесконечно, а я сразу вижу, что именно пошло не так.

<objective>
Построить `pipeline::record` — явную машину состояний записи поверх трейта `Host` (LCH-01, D-01): чистая `Machine::step`, драйвер с шагом ≤100 мс, парсер маркеров с nonce (D-11), таблица `Deadlines` (D-09, D-12), коды сбоев `FailCode` и `RecordFailure` с сообщением и подсказкой по-русски для каждого ожидания (D-05, D-08), одноразовый `exec highlights` (D-10), ожидаемый набор дублей в журнале до запуска (TAK-01), `Progress::event`. Каждый пропавший маркер — свой код по именованному дедлайну, `ALL_DONE` не подменяет `TAKE_END` (LCH-03). Всё проверяется на `FakeHost` без CS2 (TST-01, критерий успеха 5).

Purpose: это сердце фазы — единственное место, где решается, сколько ждать и что считать сбоем; `WinHost` (01-06) и приложение (01-07) только подключаются к нему.
Output: модуль `crates/pipeline/src/record/` (`mod.rs`, `machine.rs`, `markers.rs`, `deadlines.rs`, `failure.rs`), интеграционные тесты `crates/pipeline/tests/record.rs`.

Граница с 01-08 (план разделён ради бюджета контекста): этот план решает, когда и с каким кодом запись падает; 01-08 (волна 3) делает сбой самообъясняющим — `record.log` при любом исходе, хвост консоли без шума (LCH-04, D-07), строка фактов `HLAE.exe`/`cs2.exe` и «неизвестно» вместо «жива» (LCH-06, TMO-02), код `HLAE_ERROR`. | Take i, запись | только `TakeEnd(i)` — для любого i, включая последний | `Emit(TakeDone)`; i+1 < M → ожидание начала i+1; иначе `Send("quit")` → Closing | `take_run(takes[i])` от `TakeStart(i)` | `TAKE_TIMEOUT` |
| Closing | `JobEmpty` (или `GameExited` + `close_settle`) | `Finish(Ok)`, состояние Done | `game_close` | не сбой: `Terminate`, факт-предупреждение «игра не закрылась за N с — завершаю свой job», затем `Finish(Ok)` |
| любое до Closing | `GameExited` / `JobEmpty` после появления игры | сбой сразу | — | `GAME_EXITED` |
| любое | `Input::Cancel` | `Terminate` + сбой | — | `CANCELLED` (важнее дедлайнов) |

`ALL_DONE` и `TAKE_END` (LCH-03): `AllDone` никогда не засчитывается вместо `TakeEnd`. Пока машина ждёт `TakeEnd(i)` любого дубля, включая последний (i = M-1), пришедший `AllDone` — маркер не по порядку: состояние не меняется, `quit` не отправляется, дедлайн `take_run(takes[i])` продолжает идти и по истечении даёт `TAKE_TIMEOUT` с номером дубля. `AllDone` после принятого `TakeEnd(M-1)` (в Closing) — ожидаемый конец скрипта, принимается молча.
