## Граница трейта Host

### Где живёт трейт Host и его реализации

| Option | Description | Selected |
|--------|-------------|----------|
| Новый крейт crates/host | Листовой крейт без зависимостей на pipeline: трейты, WinHost под cfg(windows), фейк, заглушка для CI; windows-sys только в одном крейте | ✓ |
| Модуль pipeline::host | Без нового крейта, но pipeline обрастает Win32-кодом, фейк недоступен другим крейтам | |
| Трейт в pipeline, WinHost в app | CLI не сможет записывать общим кодом до фазы 4 | |

**User's choice:** Новый крейт crates/host

### Как фаза 1 находит свой cs2.exe и получает дескриптор

| Option | Description | Selected |
|--------|-------------|----------|
| Job Object сразу в фазе 1 | Job с KILL_ON_JOB_CLOSE до запуска HLAE; запасной путь — снимок процессов → OpenProcess → AssignProcessToJobObject | ✓ |
| Снимок процессов + OpenProcess, Job Object в фазе 2 | Меньше Win32 в фазе 1, но дважды переделывать владение процессом | |

**User's choice:** Job Object сразу в фазе 1

### Что прячет трейт Host

| Option | Description | Selected |
|--------|-------------|----------|
| Процессы + консоль + часы; ФС через пути | Файлы дублей машина не абстрагирует, фейк пишет во временную папку | ✓ |
| Всё четыре, включая ФС | Тесты в памяти без tempdir, но больше поверхности трейта | |
| Только процессы и консоль | Часы настоящие, тесты дедлайнов в реальном времени | |

**User's choice:** Процессы + консоль + часы; ФС через пути

### Основной канал консоли

| Option | Description | Selected |
|--------|-------------|----------|
| netcon основной, console.log запасной | Команды через порт (+ -afxFixNetCon после спайка), хвост console.log параллельно, одна шина с дедупликацией | ✓ |
| Только netcon | Флаки порта будут ронять задачи | |
| console.log основной, netcon только для команд | Надёжнее порта, но задержка буферизации и старое содержимое файла | |

**User's choice:** netcon основной, console.log запасной

## Ошибка в карточке и БД

### Как типизированная ошибка доходит до карточки и store

| Option | Description | Selected |
|--------|-------------|----------|
| Отдельные колонки в store | RecordFailure {code, state, message, hint, elapsed, console_tail}; колонки fail_code/fail_state/fail_hint/fail_tail; store не зависит от pipeline | ✓ |
| JSON в колонке error | Без миграции, но карточка и очередь парсят JSON, старые записи нужно отличать | |
| Только строка с префиксом кода | Минимум правок, но фазы 3–4 будут парсить строки | |

**User's choice:** Отдельные колонки в store

### Что показывает карточка упавшей задачи в фазе 1

| Option | Description | Selected |
|--------|-------------|----------|
| Блок ошибки + лестница состояний | Код, состояние, сообщение, подсказка, время, сворачиваемый хвост; лестница видна и во время выполнения | ✓ |
| Только блок ошибки, лестница в фазе 3 | Состояния только строками журнала | |
| Всё в журнале, карточка как сейчас | Не дотягивает до критерия 2 фазы | |

**User's choice:** Блок ошибки + лестница состояний

### Сколько строк консоли хранить в ошибке

| Option | Description | Selected |
|--------|-------------|----------|
| ~30 строк, без шума | Повторы сворачиваются в ×N, AFXERROR и маркеры сохраняются всегда | ✓ |
| ~100 строк как есть | Больше контекста, без фильтрации | |
| ~10 строк | Только самый конец | |

**User's choice:** ~30 строк, без шума

### В каком виде коды ошибок

| Option | Description | Selected |
|--------|-------------|----------|
| SCREAMING_SNAKE по-английски | LAUNCHER_FAILED, GAME_NOT_STARTED, CONSOLE_NOT_OPEN, DEMO_NOT_LOADED, SCRIPT_NOT_RUN, TAKE_TIMEOUT, GAME_EXITED, HLAE_ERROR, CANCELLED | ✓ |
| С префиксом класса | ENV_*, LAUNCH_*, TAKE_* — класс сбоя виден в коде | |
| Числовые E1xx/E2xx | Не читается без таблицы | |

**User's choice:** SCREAMING_SNAKE по-английски

## Дедлайны и маркеры

### Как задаются дедлайны ожиданий

| Option | Description | Selected |
|--------|-------------|----------|
| Таблица констант + один множитель в настройках | Структура Deadlines с дефолтами из research; load_wait_secs заменяется множителем «запас по времени»; тесты передают свою таблицу | ✓ |
| Все дедлайны в настройках | 8+ полей в UI, легко выставить несогласованные значения | |
| Только константы | Менять только пересборкой | |

**User's choice:** Таблица констант + один множитель в настройках

### Что делать с повторной отправкой exec highlights

| Option | Description | Selected |
|--------|-------------|----------|
| Один раз после READY, дальше только дедлайны | Нет SCRIPT в срок → SCRIPT_NOT_RUN, нет TAKE_START 0 → TAKE_TIMEOUT | ✓ |
| Один повтор, если SCRIPT не пришёл | Повтор только при потере команды портом | |
| Оставить как сейчас | Повтор до 4 раз по таймеру | |

**User's choice:** Один раз после READY, дальше только дедлайны

### Перейти на маркеры с nonce задачи уже в фазе 1

| Option | Description | Selected |
|--------|-------------|----------|
| Да: CS2C <nonce> READY\|SCRIPT\|TAKE_START n\|TAKE_END n\|ALL_DONE | Рендерер получает nonce в Config; парсер игнорирует эхо и чужой nonce | ✓ |
| Добавить SCRIPT/TAKE_START, без nonce | Риск подхватить старые строки console.log | |
| Оставить текущие маркеры | Состояния «скрипт запущен» и «дубль начался» неотличимы | |

**User's choice:** Да, nonce-маркеры

### Как считать дедлайн одного дубля

| Option | Description | Selected |
|--------|-------------|----------|
| От плана: длина шота × коэффициент + запас | Выводится из plan.json вместе с ожидаемым набором дублей; коэффициент подстраивается в фазе 4 | ✓ |
| Фиксированный потолок на дубль | Зависший короткий дубль ждёт долго | |
| Только по простою | Это DIF-06 (v2) | |

**User's choice:** От плана: длина шота × коэффициент + запас
