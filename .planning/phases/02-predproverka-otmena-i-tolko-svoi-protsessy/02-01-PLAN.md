## Phase Goal

**As a** автор роликов, который ставит задачи на запись в очередь и уходит от компьютера, **I want to** чтобы запись не начиналась в неисправном окружении, отменялась за секунды в любом состоянии и закрывала только те `cs2.exe` и `HLAE.exe`, которые запустило само приложение, **so that** ночная очередь не висит, моя собственная игра не убивается, а причина остановки видна сразу.

<objective>
Дать крейту `host` все факты ОС, которые нужны фазе 2: окна процессов своего job (D-10, LCH-05), подтверждённый выход своей игры и реестр своих игр, переживших сессию (TMO-04, D-14/TMO-07), снимок процессов, свободное место и версию файла (PRE-04, PRE-05, PRE-06, DIF-01) — на трёх реализациях (`WinHost`, `FakeHost`, `UnsupportedHost`). Хост по-прежнему только сообщает факты; политика (сколько ждать, что считать сбоем) — в `pipeline` (планы 02-03, 02-04, 02-05).

Purpose: без этих фактов предпроверка не видит Steam и чужой CS2, отмена не может подтвердить выход игры, а детектор окна ошибки HLAE не на чем строить.
Output: расширенные трейты `Host`/`Session`, новые `win/windows.rs` и `win/system.rs`, реестр своих игр, строители сценариев фейка.
</objective>

`win/mod.rs`: в `WinSession` поле `terminated_at: Option<Instant>`, ставится в `terminate()` при первом вызове. `wait_exit(limit)`: цикл до `Instant` дедлайна; на каждом шаге брать `lock(&self.shared.game)` только на один срез: `game.wait(min(100 мс, остаток))`; `Exited(code)` при (`adopted_without_job` или `self.job.active_count() == Ok(0)`) — вернуть `Exited(code)`; `Unknown(e)` — вернуть сразу; игры нет — `NotStarted`; дедлайн вышел — `Alive`. Не держать mutex `shared.game` дольше одного среза (его каждые 250 мс берёт наблюдатель). Реестр: `static OWN_GAMES: Mutex<OwnGames>` (`struct OwnGames { leftovers: Vec<Leftover>, last_exit: Option<Instant> }`, `struct Leftover { game: OwnedProc, ended: Instant }`, `Mutex::new` в `static` с `const`-конструктором; доступ только через `lock`). Handle остаётся открытым, PID заново не открывается (повторное использование PID не может подменить процесс, T-02-02). В `impl Host for WinHost` — `wait_previous_game`: цикл с паузой 100 мс; `cancel()` — `Cancelled`; вышедшие (`game.wait(0)` = `Exited`) убрать из реестра и обновить `last_exit`; если у живой записи `ended.elapsed() >= limit` — один раз `game.kill(1)` своим handle, подождать 100 мс, не вышла — вернуть `Stuck { pid, since_end, liveness }` (запись остаётся в реестре, следующая задача проверит снова); записей нет и (`last_exit` нет или прошло `>= settle`) — `Clear { waited }`.
