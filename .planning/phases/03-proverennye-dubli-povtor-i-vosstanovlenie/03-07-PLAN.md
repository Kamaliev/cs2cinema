## Phase Goal

**As a** автор роликов, который ставит задачи на запись в очередь и уходит от компьютера, **I want to** чтобы ролик собирался только из проверенных дублей, упавшую задачу можно было повторить кнопкой без повторного скачивания и планирования, а задача, прерванная падением приложения, честно помечалась «прервана», **so that** битый дубль не попадает в ролик, повтор не стоит лишнего часа, а журнал и карточка сохраняют улики всех попыток.

<objective>
Довести до пользователя восстановление после падения и повтор: при запуске приложения осиротевшая игра прошлого экземпляра завершается по сохранённой идентичности, папка игры убирается, а задача честно становится «прервана» (D-15, RET-04). Карточка задачи даёт «Повторить» (с записи), «Заново» (с начала) и «Открыть папку», показывает «Попытка N», этап сбоя, сводку по этапам и журналы прошлых попыток (D-09, D-11, D-13, OBS-02).

Purpose: после падения приложения или задачи пользователь видит, что случилось и на какой попытке, и одной кнопкой продолжает с записи, не теряя улик.
Output: изменённые `launch.rs`, `app.rs`, `jobs_page.rs`.

**Допущения:**
- Порядок при запуске — завершить осиротевший процесс, затем уборка папки игры, затем `reset_running`: живой `cs2.exe` держит копию демки, и уборка без этого не удалит её (исследование, Pattern 10).
- Завершение и ожидание (до 3 с на процесс) идут в потоке интерфейса при запуске — случай редкий: job с `KILL_ON_JOB_CLOSE` обычно закрывает игру вместе с упавшим приложением, а файл `processes.json` — страховка для игры, принятой без job.
- Кнопка готовой задачи «Папка» переименовывается в «Открыть папку» для единообразия.
</objective>
