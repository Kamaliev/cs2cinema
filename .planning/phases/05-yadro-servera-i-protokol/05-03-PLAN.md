## Phase Goal

**As a** автор, который держит сервер очереди монтажа на Linux-машине, **I want to** ставить демку в очередь командой `cs2-server submit`, выдавать раннеру токен и видеть, как задача выдаётся с арендой и эпохой, переживает обрывы и приносит результат кусками с проверкой SHA-256, **so that** цепочка «демка → сервер → раннер → ролик» проверяется без Telegram и без CS2, а токены не утекают в журналы.

<objective>
Третий срез: аренда и эпоха. Чистый автомат `rules::decide` (строка + событие + `now_ms` → новая строка, D-05) и транзакционная обёртка в `Core`; прогресс как heartbeat, ленивое и периодическое истечение аренд, обратимая потеря аренды (тот же раннер с той же эпохой возвращает задачу себе), ограждение эпохой, повторная выдача неподтверждённого `claim`, потолок выдач для «ядовитой» демки, `release`, `hello`, восстановление после перезапуска и снятие аренд при отзыве токена.

Purpose: задача не теряется (обрыв связи, перезапуск сервера), не задваивается (новая эпоха ограждает старого раннера) и не крутится по кругу (`TOO_MANY_GRANTS`). Сбой, отмена и окончательные состояния — 05-04; передача файлов — 05-05.
Output: `rules.rs`, новые методы `Core`, маршруты `progress`, `release`, `hello`, поток `sweep`, `tests/core_states.rs`, `tests/lease_http.rs`.

**Решения на усмотрение Claude (CONTEXT «Claude's Discretion», исследование Patterns 2-4, Open Question 1):**
- Числа аренды — стартовые из роадмапа: heartbeat 10 с, TTL 45 с, long-poll 25 с, `max_grants = 3`, `startup_grace_secs = 90`; все — настройки 05-01.
- Выдача остаётся одним SQL-шагом (`UPDATE … RETURNING`) внутри `BEGIN IMMEDIATE` — исключение из `decide`, разрешённое исследованием; остальные переходы идут через `decide`.
- Потеря аренды обратима и не считается сбоем: сервер никогда не роняет задачу из-за молчания раннера.
- `release` несёт `counts` (по умолчанию `true`); `counts = false` возвращает одну выдачу — фаза 6 решит, когда раннер так делает (исследование, Open Question 1).
- Прогресс без `log[]`: журнал раннера остаётся на раннере (исследование, Open Question 4).
</objective>
