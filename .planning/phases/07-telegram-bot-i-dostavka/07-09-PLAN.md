## Phase Goal

**As a** автор или друг из белого списка, **I want to** отправить боту демку файлом (до 2 ГБ через локальный `telegram-bot-api`) или ссылку FACEIT и видеть место в очереди и ход записи, **so that** готовый ролик приходит в чат новым сообщением, а при сбое приходит понятная причина — и незнакомцы не могут занять ни диск, ни очередь.

<objective>
Доставка, которая не врёт и не дублирует вслепую, и двухуровневые отчёты о сбое. Каркас доставки (`sending` до вызова, `uncertain` при тайм-ауте после отправки) есть с 07-02; здесь — полная классификация ошибок, `/resend`, сообщения другу о неясной доставке и отчёты о сбое другу и админам.

Purpose: критерий 4 целиком — ролик приходит новым сообщением, неясная отправка не повторяется вслепую, причина сбоя понятна другу и подробна для автора.
Output: доработанные `bot/deliver.rs`, `bot/notify.rs`, команда `/resend`, тесты `tests/bot_delivery.rs` и сквозной случай в `tests/bot_e2e.rs`.

**Решения (D-04; исследование Pattern 3, §4, §6, Pitfall 5; Assumptions A5):**
- Классы ошибок доставки: `maybe_delivered()` → `uncertain` (без автоповтора); 429 → остаётся `pending`, `next_try_ms = now + retry_after`; `Timeout{sent:false}`/`Io{sent:false}` → `pending`, `next_try_ms = now + 30 с`; после 5 попыток — `failed`; 403 → `failed` и `muted = 1`; прочие ответы API → `failed`. Другу (если чат не заглушён) — сообщение при `uncertain` и `failed`; отметка `final_reported_ms` у готовой задачи значит «другу сказано про исход доставки» (одно сообщение на исход).
- Предел перед отправкой: результат больше 1950 МиБ (запас до 2000 МБ Telegram, A5) — `failed` без вызова, другу «Ролик задачи #N больше лимита Telegram (≈2 ГБ); автор передаст его иначе».
- `/resend [N]` (свои задачи; без номера — последняя готовая): `sent` + `result_file_id` → `send_video`/`send_document` с `InputFile::Id` новым сообщением, `result_message_id` обновляется; `uncertain`/`failed` → сначала «Отправляю ещё раз; если ролик уже пришёл, дубль — нормально», затем `pending` с `delivery_attempts = 0` и `muted = 0` — отправляет `deliver_once` с файла; `pending`/`sending` — «ролик уже отправляется»; задача не `done` — «ролик ещё не готов».
- Фразы другу — таблица `phrase_for(code) -> Option<&'static str>` с явной строкой для каждого кода `wire::fail::KNOWN`; `friend_phrase` для неизвестных (включая `UNKNOWN`) — общая «что-то пошло не так; автор уже получил подробности». Друг не видит `fail_message`, `fail_tail` и код.
- Админ — каждый пользователь с `role = 'admin'`, `tg_id` и без `removed_at`: «Сбой задачи #N (пользователь <имя>, игрок <ник>): код <CODE>; этап <fail_state>[, фаза <phase>]; подсказка: <fail_hint>; выдач раннеру: <grants>; сообщение: <fail_message до 500 символов>» — всё через `Redactor::clean`. Если владелец задачи сам админ, он получает оба сообщения.
</objective>
