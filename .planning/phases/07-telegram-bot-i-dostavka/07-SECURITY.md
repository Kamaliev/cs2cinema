## Границы доверия

| Граница | Описание | Данные |
|---------|----------|--------|
| сеть → HTTP раннеров (`tiny_http`) | любой, кто дотянулся до порта, присылает заголовки и тело без токена | `Content-Length`, тело запроса |
| любой пользователь Telegram → `dispatch` | `from.id`, вид чата и обновления приходят от Telegram, содержимое — от пользователя | текст, документ, подпись, имя файла |
| друг из белого списка → бот | друг может прислать что угодно, по ошибке или нарочно | размер, имя, байты демки, ссылка, ник |
| `telegram-bot-api` ↔ сервер | локальный HTTP с токеном в URL; общий том файлов | `file_path` (с токеном в имени папки), `file://` |
| текст друга → ссылка FACEIT → раннер | недоверенная строка, претендующая на ссылку; сервер по ней не ходит | канонический URL, `match_id` |
| раннер → FACEIT API / CDN | исходящие запросы с ключом автора | ключ, подписанный адрес CDN |
| раннер → сервер → чат (`Failure`) | текст с машины автора виден админу и (фразой) другу | пути, хвост консоли, код сбоя |
| настройки оператора → сервер | токен бота, адрес bot-api, пути | `Secret`, `bot_api_url` |

## Открытые ниже порога

Все три — пути, которые объявленная мера не покрывает; они совпадают с находками `07-REVIEW.md` и закрываются их исправлением.

**T-07-16 (medium, Tampering): ник с bidi/U+2028/2029/U+FEFF (WR-04).** `valid_player` (`bot/commands.rs:59-88`) вызывается только из `/player` и из имени в `/adduser`. Подпись к файлу и текст после ссылки FACEIT идут через `choose_player` (`bot/ingest.rs:79-90`) и `Redactor::clean` (`secret.rs:88-100`), а он вырезает только категорию Cc (`char::is_control`): U+200E/F, U+202A-E, U+2066-9, U+2028/9, U+FEFF проходят в `jobs.player_name`. Тест `player_with_control_or_bidi_characters_is_refused` покрывает только `/player`. Вес: в cfg CS2 этот ник не попадает (раннер использует его как ключ поиска `hero_for` → `resolve_player`, в файлы идёт имя игрока из демки), остаётся искажение текста в чате, отчёте админа и `job show`. Закрыть: `valid_player` в `choose_player` и тест на подпись с U+202E.

**T-07-22 (low, DoS): зависший bot-api держит поток опроса (WR-08).** Раздельные агенты есть (`tg/http.rs:21-41`, `:129-140`), но `/resend` доставленного ролика зовёт `send_video` по `file_id` прямо из потока `bot-poll`: `commands::handle` → `deliver::resend` → `resend_by_id` (`bot/deliver.rs:297-304`, `:324-369`) → агент `transfer` (`tg/http.rs:360`) со сроком ответа до `bot_transfer_timeout_mins` (умолчание 60 мин). Пока он висит, не разбираются ни команды, ни новые файлы. Закрыть: ставить доставку в `pending` и отдавать её `deliver_once`.

**T-07-32 (medium, Information disclosure): номер чужой задачи в ответе про дубль (WR-01).** Проверки владельца в `/cancel`, `/retry`, `/resend` и «только своё» в `/status`, `/queue` на месте (таблица ниже), но `find_duplicate` (`core.rs:523`) ищет по всем пользователям, а `duplicate_text` (`bot/ingest.rs:111-126`) отвечает второму другу «уже в очереди: задача #N» / «уже готов: /resend N» с номером чужой задачи (и `/resend` ему запрещён). Раскрывается номер и состояние, действовать над ним нельзя. Закрыть: не показывать номер чужой задачи и не считать чужой готовый ролик дублем (правка в работе: `find_duplicate_for`, не закоммичена).

## Закрытые с замечанием

- T-07-27: оригинал в папке bot-api удаляется после успешного приёма, после «не похоже на демку» и после проверки дубля (`bot/ingest.rs:771`, `:777-782`); при отказе `PATH_REJECTED`, ошибке записи и падении между `submit` и `remove_file` файл остаётся (WR-06). - T-07-31: скачивание демки FACEIT не ограничено по размеру (`faceit/src/lib.rs:124`, `limit(u64::MAX)`; в выдаче FACEIT `demo_size = 0`, поэтому проверка `max_demo_bytes` до скачивания не срабатывает). Объявленная мера (дочерняя предпроверка с потолками) есть; источник — только FACEIT API по `match_id`. Это WR-06 фазы 6, ниже порога.
- T-07-43 (high): кодовые признаки есть и проверены: токен бота только в `Secret`, `expose()` в двух местах `tg/http.rs`, `Redactor` на журнале, базе и чате, в репозитории нет настоящих секретов (поиск форм `цифры:секрет`, `цифры~секрет`, `cs2r_` + hex нашёл только тестовые образцы), в командной строке сервера нет флагов с секретами, ключ FACEIT и токен раннера идут через окружение или файл. Проверка улик живого стенда не проводилась (улик нет).
- T-07-44: `logOut` и опыты на боевом боте кодом не делаются (в `HttpTg` таких методов нет); сама мера (отдельный тестовый бот) — процедура стенда, не выполнялась.
- T-07-45: умолчание `bind = 127.0.0.1:8080` и предупреждение на не-loopback (`config.rs:56`, `:401-407`, тест `non_loopback_bind_warns`); запись условия в `07-LIVE-STAND.md` не сделана (файла нет), условие оставлено в `07-11-SUMMARY.md`.
