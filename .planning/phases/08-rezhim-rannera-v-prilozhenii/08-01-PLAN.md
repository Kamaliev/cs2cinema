## Phase Goal

**As a** автор с CS2 на своём ПК, **I want to** чтобы приложение само работало раннером сервера, **so that** задача друга с сервера шла через мою обычную очередь карточкой с журналом, этапами, отменой и «Повторить», не мешала моим задачам, сама продолжалась после перезапуска, а без адреса сервера приложение работало как в v1.0.

<objective>
Трассирующий срез всей фазы: задача на настоящем `server::serve` → `runner::Runner` в потоке раннера → `RemoteExecutor` → карточка в `store` → поток очереди приложения → настоящий `PipelineExecutor` (на `FakeHost`) → итог через `SettleHook` → загрузка ролика на сервер. Здесь задаются шов «поток раннера ↔ хаб ↔ поток очереди», формат `external_ref`, миграция 6 и хук очереди; все следующие планы расширяют этот срез, не меняя его архитектуры.

Purpose: доказать в первой волне, что удалённая задача — обычная карточка единственной очереди (одна запись за раз обеспечивается одним потоком очереди, а не новым замком), и что `queue::start` при этом не меняется.
Output: `Task.epoch`, `runner::Config::new`, миграция 6 и методы карточки в `store`, `start_with_hook` в `queue.rs`, модуль `app::remote` (хаб, исполнитель, ветка очереди, стенд тестов), трассирующий тест.

**Решения автора по открытым вопросам исследования (2026-10-12), которые реализует этот план:**
- D-03: в `runner::Task` добавляется `epoch`; `external_ref = srv:{job_id}:{epoch}`.
- D-05 (часть): подпись новой карточки — «Задача с сервера #N»; игрок из задачи (очищенный), карта пуста, пока неизвестна (заполнение карты и заголовок карточки — планы 08-02 и 08-05).

**Ограничения фазы (обязательны во всех планах):** `queue::start` не меняется (хук — только через `start_with_hook`, `QueueConfig` литералом из трёх полей остаётся рабочим); `cargo test -p app queue` и `cargo test --release -p cli --test pipeline` зелёные; `crates/server` не получает зависимостей от `pipeline`/`runner`/`host`/`faceit` (сервер — только `[dev-dependencies]` приложения); одна запись за раз; без адреса сервера поведение v1.0; пользовательские строки по-русски.

**Решения на усмотрение Claude (исследование «Pattern 1-3», «Anti-Patterns»):**
- Ветка удалённой карточки — обёртка `remote::queue_runner(local, hub, factory)` над прежним `jobs::runner`; сам `jobs::runner` и его сигнатура не меняются (тест `real_runner_failure_reaches_the_row_and_the_queue_goes_on` зовёт его напрямую).
- Источник карточки — `JobSource::File(task.demo)` (демка раннера всегда `remote/srv{id}.dem`; FACEIT-ссылку скачивает `PipelineExecutor`); `wire` приложению напрямую не нужен.
- Исполнитель карточки создаётся фабрикой `ExecFactory` на каждый запуск (приложение читает настройки на каждую задачу); в тестах фабрика отдаёт `PipelineExecutor` на `FakeHost` с `with_job_fn`.
- Будить очередь через `Queue::resume()` нельзя (он снимает паузу): карточку поток очереди находит на очередном такте.
</objective>
