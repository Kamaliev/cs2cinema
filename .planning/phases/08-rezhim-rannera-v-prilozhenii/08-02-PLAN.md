## Phase Goal

**As a** автор с CS2 на своём ПК, **I want to** чтобы приложение само работало раннером сервера, **so that** задача друга с сервера шла через мою обычную очередь карточкой с журналом, этапами, отменой и «Повторить», не мешала моим задачам, сама продолжалась после перезапуска, а без адреса сервера приложение работало как в v1.0.

<objective>
Раннер получает то, без чего приложение не может быть его хозяином: ворота допуска перед `claim` (удалённая задача берётся только при свободной очереди приложения), наблюдатель состояния (окно показывает связь с сервером) и факты о демке после предпроверки (карта и игрок для подписи карточки). `cs2-cli runner` при этом не меняет поведения: у него ворот и наблюдателя нет.

Purpose: APP-02 решается в раннере, а не замком между потоками: закрытые ворота — нет `claim`, гонка «ворота открыты → выдача → автор поставил задачу» закрывается повторной проверкой и `release(counts: false)`.
Output: `Admission`/`Gate`, `Tick::Gated`, `RunnerEvent`/`Observer`, `Runner::holding`, `Artifact::Match`, `Preflight.map`, обновлённые тексты `USAGE_RUNNER` и подсказки о ключе FACEIT, тесты `gate.rs` и `observer.rs`.

**Решения автора, которые затрагивает план:**
- D-03: эпоха уже в `Task` (08-01); события наблюдателя несут пару (`job_id`, `epoch`), по ней приложение находит карточку (`external_ref`).
- D-05: карта и игрок для подписи карточки приходят из ответа дочерней предпроверки (`Artifact::Match`); запись в карточку — план 08-05.

**Ограничения фазы:** `crates/server` не меняется; `cs2-cli runner` собирается и проходит свои тесты; одна запись за раз; строки по-русски.

**Решения на усмотрение Claude (исследование «Pattern 4», «Pattern 5», A2, A3):**
- Наблюдатель — поле `Config.observer`, а не `run_observed`: события нужны изнутри `tick` (связь, работа, итог), сигнатура `run()` не меняется.
- A2 подтверждён кодом: любой запрос с токеном обновляет `runners.last_seen_at` (`server::auth::authenticate`), поэтому `hello` раз в 30 с держит раннер «на связи» при окне `longpoll_secs*1000 + lease_ttl_ms`. A3: сервер принимает `claim?wait=N` любого `N ≤ longpoll_secs`.
- Если `release` после закрытия ворот не прошёл (сеть), задача принимается как обычно и ждёт в очереди приложения: одна запись всё равно обеспечена единственным потоком очереди.
- `Artifact::Match` отправляет исполнитель раннера после дочерней предпроверки (ответ ребёнка уже содержит `map`), а не `run_job`: так `run_job` и локальные задачи v1.0 не меняются.
</objective>
