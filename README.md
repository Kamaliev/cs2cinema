# cs2-cli — хайлайт-ролик из матча FACEIT

Консольная утилита: даёшь ссылку на матч FACEIT (или файл демки) — получаешь монтажный план хайлайтов
для CS2: отбор моментов по score, камеры (41 пресет, пролёты, зумы, слоумо) с учётом стен карты,
скрипт для записи через HLAE и склейку ffmpeg.

Статус: разбор демок, хайлайты, режиссёр и стены проверены на реальной демке FACEIT (сверка с demoparser2).
Запись в CS2 через HLAE 2.192.7 и склейка проверены целиком на Windows 11 (октябрь 2026): 5 шотов → `highlights.mp4`.

## Установка (Windows)

### Вариант А. Готовый exe (проще всего)

Одной командой в PowerShell (скачает последний релиз, проверит хэш, добавит `cs2-cli` в PATH):

```powershell
irm https://raw.githubusercontent.com/Kamaliev/cs2cinema/main/install.ps1 | iex
```

Или вручную:

1. Откройте https://github.com/Kamaliev/cs2cinema/releases и скачайте `cs2cinema-windows-x64.zip`
   (релизы собирает GitHub Actions по тегу `v*`; пока релизов нет — берите вариант Б или артефакт из вкладки *Actions*).
2. Распакуйте в любую папку без пробелов, например `C:\cs2cinema`.
3. Поставьте то, что нужно в работе:
   * **Git** — https://git-scm.com/download/win (программа вызывает `git`, чтобы узнать свежий релиз карт);
   * **ffmpeg** (в `PATH`) — склейка клипов в итоговый ролик, `winget install Gyan.FFmpeg`;
   * **HLAE** — запись в CS2, https://github.com/advancedfx/advancedfx/releases;
   * **Python 3.11+** — только для `scripts\update_maps.py` (геометрия карт из файлов игры), необязательно.
4. Проверка: откройте PowerShell в папке и выполните `.\cs2-cli.exe --list-cameras` — должен напечатать таблицу из 41 камеры.

### Вариант Б. Сборка из исходников

1. Поставьте **Git**, **Git LFS** (идёт вместе с Git for Windows) и **Rust** — https://rustup.rs.
   Rust на Windows попросит **Visual Studio Build Tools** с набором «Desktop development with C++» —
   согласитесь, без него не соберутся `zstd` и `ring`.
2. В PowerShell:

```powershell
git clone https://github.com/Kamaliev/cs2cinema
cd cs2cinema
git lfs pull                               # демка из репозитория, 283 МБ (нужна только для проверки)
cargo build --release -p cli               # ~2-4 мин в первый раз
.\target\release\cs2-cli.exe --list-cameras
```

Или одной командой, если Rust уже стоит (бинарь попадёт в `~\.cargo\bin`, он уже в PATH):

```powershell
cargo install --git https://github.com/Kamaliev/cs2cinema cli
```

Все тесты: `cargo test --release` (тесты на реальной демке запустятся только с переменными ниже).

## Быстрый старт

```powershell
# локальная демка (.dem, .dem.zst, .dem.gz): только список хайлайтов
.\cs2-cli.exe C:\demos\match.dem --list

# полный прогон: монтаж + файлы для записи в папку out\test
.\cs2-cli.exe C:\demos\match.dem --out out\test --length 60

# ролик про одного игрока: все его убийства и важные гранаты по порядку, с пролётами
.\cs2-cli.exe C:\demos\match.dem --player Sihnel --out out\sihnel

# матч по ссылке FACEIT (ключ Data API с доступом к Downloads API: https://developers.faceit.com)
$env:FACEIT_API_KEY = "ваш-ключ"
.\cs2-cli.exe https://www.faceit.com/en/cs2/room/1-xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
```

При первом запуске программа сама скачает геометрию карты (~60 МБ на все карты) в `.\maps`.
Результат в `out\<матч>\`: `plan.json` (монтажный план), `highlights.cfg` (скрипт для CS2/HLAE;
и `cs2c_NN.cfg` по одному на шот — программа сама кладёт их в `game\csgo\cfg`, если нашла CS2),
`campath_NN.xml` (пути свободной камеры),
`assemble.bat` / `assemble.sh` + `assemble.ffgraph` (склейка через ffmpeg 7+).
Сжатую демку (`.dem.zst`) программа сохраняет рядом распакованной — CS2 открывает только `.dem`.

| параметр | что делает |
|----------|------------|
| `--out <папка>` | куда писать результат (по умолчанию `out\<id матча>`) |
| `--length <сек>` | целевая длина ролика (60) |
| `--max-shots <N>` | максимум моментов (12) |
| `--chronological` | по порядку матча, а не «от слабого к лучшему» |
| `--player <ник>` | ролик про одного игрока по раундам: раунд его глазами, сразу после — один дополнительный ракурс на сильное убийство (повтор со стороны или глазами противника), полёт гранаты и её взрыв глазами того, кого под неё убили; лучший раунд — в финале; раунды без убийств не берутся |
| `--detailed` | с `--player`: весь KAST (раунды с ассистом или разменом, все важные гранаты) и все ракурсы на каждое убийство — в ~2 раза длиннее |
| `--cinematic` | в обычном монтаже любой момент подаётся «как эпик»: пролёт-интро, смена ракурса на убийствах, пролёт в финале |
| `--demo <N>` | номер карты в bo3 (с нуля) |
| `--fps <N>` | fps ролика (60); fps записи каждого шота программа считает сама — выше там, где есть замедление |
| `--size <ШxВ>` | размер кадра ролика = размер окна игры при записи (1280x720) |
| `--list` | только показать хайлайты |
| `--list-cameras` | каталог камер |
| `--no-flybys` | без позиций игроков и свободных камер (быстрее) |
| `--no-walls`, `--maps <папка>`, `--refresh-maps`, `--offline` | геометрия карт, см. «Актуальность геометрии карт» |

## Оконное приложение

После установки найдите **CS2 Cinema** в меню «Пуск» (или запустите `cs2cinema.exe`). Окно висит на панели задач,
крестик сворачивает его в трей (значок возле часов). Внизу — строка состояния: этапы
`Скачивание › Разбор › Позиции › Геометрия › План › Запись › Склейка › Готово`, текущее действие и журнал.

Страницы:

* **Игрок** — ник на FACEIT → сводка за последние 20 матчей (винрейт, K/D, ADR, HS%, K/R), таблица по картам
  и список матчей с вашими K-D-A, K/D и ADR. «Открыть» ведёт на страницу матча.
* **Матч** — таблица FACEIT (по командам и игрокам, ваша строка подсвечена) и **разбор по демке**:
  «Скачать и разобрать демку» (или перетащите `.dem`/`.dem.zst` в окно, `cs2cinema.exe demo.dem`).
  Вы находитесь в демке по SteamID из FACEIT, иначе по нику; другого игрока можно выбрать в списке.
  Разбор: дуэли (открывающие убийства и смерти, трейды, убийства по оружию), гранаты по видам (брошено,
  ослеплено врагов и среднее ослепление, урон, убийства; лучшие гранаты), раунды (исход, убийства, выжил ли,
  гранаты и их эффект) и ваши моменты.
  **«Собрать ролик про меня»** — то же, что `cs2-cli --player`: раунды с вашими убийствами вашими глазами
  (плашка «Раунд 12 · CT · 7:4» поверх кадра), сразу после куска — повтор или взгляд противника на сильный момент,
  полёт гранат и их взрыв глазами того, кого под них убили; заставка с итогами в конце; лучший раунд — в финале.
  Приложение строит план, кладёт скрипты и демку в игру,
  запускает CS2 через HLAE, отправляет `exec highlights` через консольный порт, ждёт дубли, склеивает их ffmpeg
  и открывает `highlights.mp4`. «Только план и скрипты» делает лишь файлы.
  Если консоль игры не ответила, выполните `exec highlights` в консоли CS2 вручную — дальше всё пойдёт само.
* **Задачи** — очередь и история задач на монтаж карточками: превью готового ролика, статус, прогресс записи
  (дубль N из M) и склейки, длина и размер. Задача — отдельная сущность: откуда демка (матч FACEIT
  или файл), про кого ролик (ник и SteamID), план или запись, статус и этап, журнал, результат.
  Задачи лежат в SQLite (`%LOCALAPPDATA%\cs2cinema\cs2cinema.db`), переживают перезапуск и выполняются
  по одной (CS2 пишет только одну). Кнопки: «Отменить» (из очереди — сразу; выполняемую — на ближайшем
  этапе или ожидании, при отмене во время записи игра закрывается), «Повторить», «Открыть», «Папка»,
  «Журнал», «Удалить». В той же базе — кэш статистики матчей FACEIT (статистика сыгранного матча не
  меняется, так что запрашивается один раз) и реестр скачанных демок.
* **Настройки** — ключ FACEIT Data API и ник, папки HLAE / CS2 / результатов (CS2 ищется в Steam, HLAE — на дисках
  автоматически; пути проверяются на месте), fps, разрешение и ожидание загрузки, параметры монтажа
  («Подробный ролик» = `--detailed`, порядок раундов, пролёты, стены), трей и автообновление.
  При первом запуске сверху — подсказка «три шага до первого ролика».
  Настройки лежат в `%LOCALAPPDATA%\cs2cinema\settings.json`.

В FACEIT-демках у конца раунда нет победителя: он выводится по бомбе (взрыв — T, разминирование — CT),
по «всю команду выбили», иначе — CT (время вышло).

Приложение само проверяет новые релизы на GitHub и предлагает обновиться (сверяет SHA-256 и перезапускается).

Запуск CS2/HLAE из окна не проверялся на живой игре (в окружении разработки нет Windows и CS2) — если что-то
не стартует, пришлите текст из журнала внизу окна.

## Запись в игре (HLAE)

1. В HLAE укажите ffmpeg: `ffmpeg\ffmpeg.ini` в папке HLAE (`[Ffmpeg]` / `Path=...\ffmpeg.exe`), иначе запись не начнётся
   (`AFXERROR: COutFFMPEGVideoStream ... CreateProcessW`).
2. Запустите CS2 через HLAE (*Launch CS2*, параметры `-insecure -console`). Без HLAE команды `mirv_*` не существуют
   и скрипт ничего не делает. Из командной строки:

   ```powershell
   & "C:\Program Files (x86)\HLAE\HLAE.exe" -customLoader -noGui -autoStart `
     -hookDllPath "C:\Program Files (x86)\HLAE\x64\AfxHookSource2.dll" `
     -programPath "C:\Program Files (x86)\Steam\steamapps\common\Counter-Strike Global Offensive\game\bin\win64\cs2.exe" `
     -cmdLine "-steam -insecure -console -novid"
   ```
3. В консоли CS2 — команды, которые напечатал `cs2-cli`: `demo_ui_mode 0; playdemo "C:/путь/к/демке.dem"` (без `demo_ui_mode 0` в кадр попадёт полоска проигрывателя), а когда демка загрузится —
   `exec highlights`. Скрипт прячет HUD (остаётся килфид), перематывает демку, переключает камеры и зум
   и пишет каждый шот дублем `out\<матч>\clips\takeNNNN\video.mp4` + `audio.wav`. Окно игры можно сворачивать:
   скрипт выставляет `engine_no_focus_sleep 0`, иначе CS2 без фокуса спит 20 мс на кадр и запись идёт в разы дольше.
4. Запустите `out\<матч>\assemble.bat` — получится `highlights.mp4` со звуком: замедление (видео и звук через
   `atempo`), подписи в кадре, заставки раундов и жёсткие склейки делаются здесь одним проходом ffmpeg по
   `assemble.ffgraph`. Шрифт подписей — Arial Bold из Windows (`$CS2CINEMA_FONT` — свой).

`cs2-cli` при каждом запуске откладывает прошлые дубли в `clips_old_<время>` (HLAE нумерует дубли подряд,
и склейка взяла бы старые); если план не менялся, верните папку обратно в `clips` и не перезаписывайте.

Шоты пишутся в порядке показа: каждый `cs2c_NN.cfg` ставит свои команды и в конце вызывает следующий,
перематывая демку куда нужно — в том числе назад. Поэтому моменты могут перекрываться: например,
пролёт за гранатой, а затем то же убийство с других ракурсов.

**Ролик про игрока (`--player`, в окне — «Собрать ролик про меня»)** — весь полезный KAST игрока за игру,
по раундам. Берётся каждый раунд, где он убил, ассистировал (уроном или флешкой) или его смерть разменяли:

1. раунд его глазами — кусками вокруг действий (убийств, ассистов, бросков, смерти перед разменом),
   пустой бег между ними вырезается; обычная скорость; перед раундом — заставка
   «Раунд N · 3 убийства · 1 ассист · 2 флешки · размен»;
2. режиссура — повторы со стороны только на сильных моментах (серия 2+, убийство сквозь дым/стену,
   без прицела, нож…); ракурс берётся, лишь если в момент выстрела видно и убийцу, и жертву;
   приближение (зум) — только на дальних дуэлях (от 25 м), иначе без него;
3. пики глазами противника: с момента, когда игрок у него появился (в поле зрения, без стены),
   с замедлением; если противник игрока так и не увидел — камера из-за его плеча, развёрнутая туда,
   откуда игрок вышел (если и оттуда не видно — вставки нет);
4. размен — глазами тиммейта, который отомстил.

**Гранаты.** Саму гранату игра рендерит, так что траектория настоящая: камера стоит из-за плеча
бросившего и, пока путь свободен, подъезжает по земле к точке взрыва (на высоте глаз, над крышами не
летает, в стены не входит — каждый шаг проверяется лучом по геометрии). После взрыва — общий план
вблизи (≤ 320 юнитов, чуть выше роста, по возможности со стороны бросавшего), на котором видно
взрыв и пострадавших; если чистого ракурса нет, общего плана нет. Затем взрыв глазами тех, кого
граната решила: убитых под ней, иначе одного самого ослеплённого (или до двух раненых) — коротко,
с замедлением. Убийство под флешку — повтор со стороны, где видно и убийцу, и ослеплённого,
с подписью «Под флешку X · Y убивает Z» (нет ракурса — глазами убийцы). Флешки, взорвавшиеся
с разницей до 3 с, — один залп: один полёт и один набор вставок; ослепление короче 1.2 с не показывается.
У каждого участка свободной камеры свой путь `cs2c_NN_K.xml` в `game\csgo\cfg` (HLAE грузит его относительным
путём от `game\bin\win64`), поэтому склейки между участками чистые.

Почему так (выяснено в игре): `spec_player_by_accountid` в CS2 нет — используется `spec_player <слот+1>`;
`spec_mode` 2 = от первого лица, 3 = chase, 4 = свободная камера; HLAE пишет с фиксированным шагом времени,
поэтому `host_timescale`/`demo_timescale` замедления не дают — запись идёт с повышенным fps
(`mirv_streams record fps`, 60 / самое сильное замедление), а `setpts` растягивает кадры при склейке;
время campath — время игры (`(тик демки + server_start_tick) / 64`), углы в XML: rx — крен, ry — тангаж, rz — рыскание;
консоль режет аргументы по `:`, а `mirv_cmd` теряет кавычки — абсолютные пути задаются один раз в начале скрипта.

## Запись из консоли

Тот же код, что гоняет очередь в приложении (`pipeline::job::run_job`), доступен из консоли: игра запускается,
дубли проверяются, ролик склеивается — без окна.

```powershell
$env:FACEIT_API_KEY = "ваш-ключ"          # нужен только для ссылки FACEIT
$env:HLAE_DIR = "C:\Program Files (x86)\HLAE"
$env:CS2_DIR  = "C:\Program Files (x86)\Steam\steamapps\common\Counter-Strike Global Offensive"

# полная задача: предпроверка → демка → план → запись с проверкой дублей → склейка
.\cs2-cli.exe record https://www.faceit.com/en/cs2/room/1-xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx --player Sihnel

# повтор упавшей задачи по record.json из её папки: без скачивания и плана; если дубли уже проверены — сразу склейка
.\cs2-cli.exe retry out\<папка задачи>

# только склейка: берёт record.json и clips\manifest.json, пишет highlights.mp4 через временный highlights.part.mp4
.\cs2-cli.exe assemble out\<папка задачи>
```

* `cs2-cli record <ссылка FACEIT | .dem> --player <ник> [--hlae <папка>] [--cs2 <папка>] [--out <папка>] [--size ШxВ] [--fps N] [--margin X] [--no-gpu]` —
  `--hlae` и `--cs2` по умолчанию берутся из `HLAE_DIR` и `CS2_DIR` (поиска по дискам в консоли нет);
  `--margin` — множитель дедлайнов; `--no-gpu` — без кодирования на видеокарте.
* `cs2-cli retry <папка задачи> [--hlae] [--cs2] [--margin] [--no-gpu]` — «Повторить» из окна.
* `cs2-cli assemble <папка задачи>` — склейка тем же кодом, что в приложении (`pipeline::assemble`).
* Ошибка печатается как `ошибка: КОД: сообщение` и `подсказка: …`; код выхода 1 — сбой задачи, 2 — ошибка в аргументах.
* Закрытие консоли закрывает и запущенную игру (она живёт в Job Object процесса).

## Проверка на реальных данных

```powershell
$demo = (Get-Item .\1-3e7db9e3-*-1-1.dem).FullName   # демка из репозитория (после git lfs pull)
$env:CS2_TEST_DEMO = $demo
$env:CS2_TEST_MAPS = (Resolve-Path .\maps)            # папка появится после первого запуска cs2-cli
cargo test --release -p positions --test real_demo -- --nocapture
```

Тесты сверяют число убийств, позиции и углы игроков и то, что камеры не пролетают сквозь стены.

## Если что-то не работает

* **`linker 'link.exe' not found` при сборке** — не поставлены Visual Studio Build Tools (см. вариант Б).
* **`не удалось запустить git`** — Git не в `PATH`; перезапустите PowerShell после установки или используйте `--offline`.
* **`FACEIT отказал в доступе`** — проверьте `FACEIT_API_KEY` и что у ключа есть доступ к Downloads API.
* **«если файл — LFS-заглушка, сделайте git lfs pull»** — вместо демки лежит указатель Git LFS (134 байта).
* **Команда в консоли CS2 не сработала** — пришлите текст ошибки; команды собраны в одном месте,
  `crates/renderer` (`Dialect`), и правятся без изменений в остальной логике.

## Устройство (по крейтам)

| крейт        | что делает |
|--------------|------------|
| `faceit`     | ссылка → id матча → demo_url → скачивание `.dem.zst` |
| `demo`       | контейнер демки, protobuf, вложенные сообщения пакетов, игровые события, `userinfo` |
| `cs2`        | модель матча: раунды, убийства, игроки |
| `highlights` | серии убийств и эффектные одиночки + score |
| `director`   | монтаж: отбор по score, POV/chase/свободная камера, кривая замедления и зума |
| `positions`  | позиции, взгляд, команда и «жив» по тикам из состояния сущностей (`source2-demo`) |
| `geometry`   | коллизионные меши карт (awpy-data), BVH, трассировка лучей — для стен |
| `renderer`   | `plan.json`, `highlights.cfg` + `cs2c_NN.cfg` для HLAE, `campath_NN.xml`, `assemble.sh`/`assemble.bat` + `assemble.ffgraph` (ffmpeg) |

CI (`.github/workflows`): `ci.yml` гоняет тесты на Linux и Windows и выкладывает `cs2-cli.exe` артефактом;
`release.yml` по тегу `v*` собирает `cs2cinema-windows-x64.zip` и публикует GitHub Release
(`git tag v0.1.0 && git push origin v0.1.0`) или кнопкой: *Actions → Release (Windows) → Run workflow*, поле `tag`.

## Камеры (`crates/director/src/rig.rs`)

41 пресет в таблице `PRESETS`: орбиты, наезды/отъезды, краны, ракурсы, широкие планы, раскрытие через
жертву, групповые планы, вайпы взглядом, зумы (punch-in, snap, dolly zoom). `cs2-cli --list-cameras`
печатает каталог с оценками на тестовой сцене.

Для каждого окна (интро, нарезка на средних убийствах, финал) режиссёр строит путь каждого подходящего
пресета и считает красочность 0..1:

| компонент | вес | что меряет |
|-----------|-----|------------|
| видно килл | 0.30 | убийца и жертва в кадре, в момент убийства вес ×3 |
| людность   | 0.16 | сколько ещё игроков в кадре (до 4) |
| кадр       | 0.12 | герой ближе к центру, комфортная дистанция |
| плавность  | 0.10 | угловая скорость (для вайпов лимит выше) |
| подача     | 0.12 | драматичность пресета vs tier хайлайта |
| разнообразие | 0.20 | штраф за повтор пресета/категории |

Камера внутри игрока обнуляет оценку.

**Стены.** В демке геометрии карты нет — она в файлах игры. Берём готовые коллизионные меши сообщества
([awpy-data](https://github.com/pnxenopoulos/awpy-data), релиз `geometry.zip`, 24 карты, формат `AWMH`).
Они принадлежат Valve, поэтому в репозитории не хранятся: при первом запуске скачиваются в `./maps`
(`--maps <папка>` или `$CS2CINEMA_MAPS`; `--no-walls` — без стен). С геометрией:

* «пружинный подвес»: если между героем и камерой стена, камера подтягивается к герою;
* кадры, где убийца или жертва закрыты стеной, не получают баллов за «видно килл»;
* пролёт камеры сквозь стену режет оценку в 3 раза.

На демке из репозитория без стен в плане было 9 закрытых кадров из 20 и 5 пролётов сквозь стены, со стенами — 0 и 0.
Меш упрощён и содержит только окклюдеры (без playerclip/glass), двери и динамические объекты не учтены.
Зум POV-камер — кривая `zoom` (множитель FOV → `mirv_fov`), рядом с замедлением на убийствах;
у снайперских убийств зум глубже.

## Актуальность геометрии карт

Карты меняются с обновлениями игры, поэтому меши привязаны к версии игры (`maps/maps.json`):

* **По умолчанию** `cs2-cli` раз в сутки сверяется с последним релизом awpy-data (по тегам; тег = ClientVersion
  игры) и при выходе нового скачивает меши заново. Сеть недоступна — работает на сохранённых.
  `--refresh-maps` — сверить сейчас, `--offline` — не ходить в сеть.
* **Из файлов вашей игры**: `python3 scripts/update_maps.py` находит CS2 (Steam, все библиотеки из
  `libraryfolders.vdf`, либо `--cs2-dir` / `$CS2_DIR`), читает ClientVersion из `steam.inf` и, если меши
  старее игры, извлекает физику карт через Source2Viewer-CLI и конвейер awpy-data, затем записывает
  меши и версию в `maps/`. `--check` только сообщает «актуально / нужно обновить» (код выхода 0/1).
  Такие меши `cs2-cli` не перезаписывает релизом; если игра обновилась после извлечения, он напишет
  «запустите scripts/update_maps.py».

Скрипту нужны Python 3.11+ и git; Source2Viewer-CLI скачивается сам (все ОС и архитектуры).
На поддельной установке проверены: поиск игры, клонирование конвейера, скачивание и запуск Source2Viewer-CLI,
метка версии, логика «актуально/устарело». Реальное извлечение из VPK я проверить не мог — игры в среде нет;
конвейер awpy-data сам помечает пути внутри VPK как `TODO(verify)`, хотя его CI-релизы строятся этим же кодом.

## Проверено на реальной демке

Демка FACEIT из репозитория (de_nuke, 283 МБ), сверка с независимым парсером `demoparser2`:

* события: 173 убийства после `begin_new_match` — совпадает;
* позиции: расхождение ≤ 0.8 юнита (интерполяция между замерами), «жив/мёртв» 100%;
* углы: у `source2-demo` `m_angEyeAngles` сдвинуты на 180° (pitch и yaw) — в `positions` исправлено;
  на убийствах стрелок смотрит на жертву у 170 из 173 (медиана 0.6°);
* весь прогон (разбор + позиции + монтаж) ≈ 5 с.

Тесты на реальной демке: `CS2_TEST_DEMO=/path/to/match.dem cargo test --release -p positions`
(без переменной пропускаются). Для проверок со стенами добавьте `CS2_TEST_MAPS=<папка с *.mesh>`.
Луч «стрелок → жертва» чист у 145 из 158 обычных убийств (92%) — геометрия и демка в одной системе координат.

Особенности FACEIT-демок (SourceTV): нет событий `round_start`/`round_end` — раунд начинается на
`round_prestart`; `round_prestart` идёт за ~1 с до `begin_new_match`, поэтому этот раунд сохраняется.

## Что не проверено / не сделано

* Запись проверена на одной демке (de_nuke) и одной версии HLAE; команды собраны в `crates/renderer`
  (`Dialect` и начало `highlights.cfg`) — если после обновления CS2/HLAE что-то перестанет работать, правьте там.
* Меши карт соответствуют версии игры релиза awpy-data, а не патчу демки; после обновления карты возможны расхождения.
* Разбор сущностей (`crates/positions`) делает `source2-demo` (MIT/Apache-2.0), а не собственный
  код проекта; он спрятан за `positions::Track`, который реализует `director::PositionSource`,
  так что заменяется без правок в остальных крейтах.
* Клатчи пока не определяются (теперь есть всё нужное: `Track::team_at` и `is_alive`).
