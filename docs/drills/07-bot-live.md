# 07-bot-live: живые учения бота

Учение проводит автор в плане 09-10. Правила, роли, формат `RESULT.md` и правило кодировки — в `docs/drills/README.md`. Общие приёмы (`ctl`, сборщики, перенос файлов в сырую папку) — в `docs/drills/00-stand.md`, раздел «Общие приёмы».

## Цель

Закрыть 07-UAT тест 4: «Учения вживую: незнакомец, FACEIT от друга, `/cancel`, `/retry`, `/status`, `/queue`, сбой задачи». В тестах фазы 7 бот проверен только на `FakeTelegram` и `FakeHost`; здесь он отвечает настоящим людям в настоящем Telegram, поверх настоящего сервера и раннера. Ожидание: ответы по-русски, без локальных путей и кодов сбоя у друга, отчёт автору с кодом, улики сохранены.

Роли: `автор` (админ), `друг` (аккаунт с доступом), `незнакомец` (второй аккаунт без доступа). В репликах, заметках и уликах — только роли.

## Предусловия

1. Стенд из `docs/drills/00-stand.md` готов, живая цепочка пройдена. Других учений на стенде нет (одна запись за раз).
2. Раннер — приложение `cs2cinema.exe` в режиме раннера, запущено и «на связи».
3. Три аккаунта Telegram: `автор` (админ, получает отчёты о сбоях), `друг` (добавлен командой `/adduser`, имя пользователя на сервере — `друг`), `незнакомец` (не добавлен). Настоящая ссылка FACEIT на доигранный матч, где есть ник игрока с моментами; настоящая демка; один мусорный файл с расширением `.dem` (например, переименованный текстовый файл).
4. Сырая папка `%LOCALAPPDATA%\cs2cinema\drills\raw\07-bot-live` и папка улик `.planning/phases/09-uborka-razvertyvanie-i-ucheniya/evidence/07-bot-live` не существуют (правило повтора README); на хосте нет `~/drill/07-bot-live` и `~/raw/07-bot-live`.
5. Файл образцов секретов `%LOCALAPPDATA%\cs2cinema\drills\patterns.txt` лежит вне репозитория.

## Шаги

### Подготовка

1. Хост: `date '+%Y-%m-%d %H:%M:%S'` — `<начало>` для сборщика; `ctl` определена как в `docs/drills/00-stand.md`.
2. Windows, из корня репозитория: `$raw = "$env:LOCALAPPDATA\cs2cinema\drills\raw\07-bot-live"` и `New-Item -ItemType Directory -Force $raw | Out-Null`.
3. `chat.txt` ведётся по ходу учения руками (UTF-8): каждая реплика отдельной строкой с ролью (`незнакомец:`, `друг:`, `автор:`, `бот→незнакомцу:`, `бот→другу:`, `бот→автору:`). При записи заменять: Telegram-ID — на `<ID>` (ответ бота незнакомцу содержит ID самого незнакомца, это задумано, но в улики он не идёт), ник игрока — на `<ник>`, ссылку FACEIT — на `<ссылка FACEIT>`, локальные пути, если бы они появились, — оставить как есть (их появление и есть провал, см. «Чего быть не должно»).

### Сценарий

Каждый шаг — реплика роли и проверка ответа; ответы записываются в `chat.txt`. Номера задач `<N1>`, `<N2>`, … берутся из `ctl job list`.

1. `незнакомец` пишет боту любое сообщение. Ожидание: вежливый отказ без подробностей («Бот работает только для друзей автора…» и его ID с просьбой передать автору); задача не создана (`ctl job list` не растёт); повторное сообщение в ближайшие 10 минут остаётся без ответа.
2. `друг`: `/start` — ответ-инструкция по-русски. `/player <ник>` — ответ «Игрок: <ник>».
3. `друг` присылает ссылку FACEIT доигранного матча (без ника в сообщении — ник берётся из `/player`). Ожидание: «Принял ссылку на матч FACEIT для игрока … Демку скачает раннер.»; номер задачи `<N1>`.
4. Пока `<N1>` идёт: `друг` отправляет `/status` (список «Мои задачи» с этапом и местом в очереди) и `/queue` (общая очередь и места задач друга). Статусное сообщение обновляется не чаще раза в 10 секунд. Дождаться ролика в чате: он приходит новым сообщением, воспроизводится.
5. `друг` присылает мусорный файл с расширением `.dem`. Ожидание: «Принял файл…», затем у `друга` сообщение «Задача #<N2> не получилась: демка повреждена или это не демка CS2. Повторить: /retry <N2>» (без кода сбоя и без путей), а у `автора` — подробный отчёт «Сбой задачи #<N2> (пользователь друг, игрок …): код BAD_DEMO; этап …; подсказка: …; выдач раннеру: …».
6. `друг`: `/retry <N2>`. Ожидание: ответ про новую задачу `<N3>` (повторяется та же мусорная демка, задача снова падает с той же понятной фразой; важно, что создалась новая задача, а не изменилась старая).
7. `друг` присылает настоящую демку (`<N4>`) и, когда запись пошла, отправляет `/cancel <N4>`. Ожидание: «Отменяю задачу #<N4> — раннер остановит запись.», затем «Задача #<N4> отменена.»; `ctl job show <N4>` — `cancelled`; раннер освободился (приложение не зависло).
8. `друг`: `/resend <N1>` по готовой задаче. Ожидание: ролик приходит ещё раз тем же файлом; на `/resend` по чужой или неготовой задаче — «Это не ваша задача.» или фраза «ещё идёт».
9. `автор` проверяет `/users` (админская команда) — список ролей, без чужих людей (Telegram-ID в `chat.txt` заменить на `<ID>`); `друг` вызывает `/users` — «Эта команда только для администратора.».

### Завершение

1. Состояние раннера (из корня репозитория): `powershell -NoProfile -File docs\drills\collect-runner.ps1 -Out "$raw\_tmp"`, затем `Move-Item "$raw\_tmp\*" $raw` и `Remove-Item "$raw\_tmp"`.
2. Хост: `sudo bash docs/drills/collect-server.sh ~/raw/07-bot-live "<начало>" <N1> <N2> <N3> <N4>`. Он собирает `server-journal.txt`, `job-list.txt`, `job-show-<N>.txt`. Скопировать `~/raw/07-bot-live/*` в `$raw` (приём из `docs/drills/00-stand.md`).
3. Руками (UTF-8): `chat.txt` (см. подготовку), `notes.txt` (что показалось странным, времена), `verdict.txt` — одна строка `pass` или `fail` и почему.

## Ожидаемый исход

1. `незнакомец` получает один вежливый отказ без подробностей (кроме собственного ID), задач от него нет, повтор в течение 10 минут молчание.
2. Все ответы бота `другу` и `незнакомцу` по-русски и без локальных путей; у `друга` нет кодов сбоя (`BAD_DEMO`, `TOO_MANY_GRANTS` и подобных) — только человеческие фразы вида «демка повреждена или это не демка CS2».
3. `автор` получил отчёт о сбое мусорной демки с кодом `BAD_DEMO`, этапом, подсказкой и числом выдач; хвост журнала раннера в чат не попал (он остаётся в `job show`).
4. Задача по ссылке FACEIT дошла до ролика, `job-show-<N1>.txt` содержит `доставка в Telegram: sent`; `/status` и `/queue` отвечают осмысленно; `/retry` создал новую задачу; `/cancel` остановил запись; `/resend` прислал ролик ещё раз.
5. Каждая реплика сценария имеет ответ; `chat.txt` содержит ответы по всем девяти шагам.

## Чего быть не должно

- Локальных путей (`C:\Users\…`, `/var/lib/…`), кода сбоя, хвоста консоли, токена или SteamID/Telegram-ID других людей в сообщениях `другу`.
- Доступа незнакомца к чему-либо: задач от него, ответов по командам, ролика.
- Двух роликов на одну задачу, молчания на команду, зависшей задачи, падения бота или сервера.
- Отчёта о сбое у `друга` с подробностями автора или, наоборот, отсутствия отчёта у `автора`.
- Токена раннера или бота в журналах, в `notes.txt`, в `chat.txt`; настоящих имён, Telegram-ID, ников и ссылок в `chat.txt` (только роли и заглушки); экспорта чата и копий базы в папке улик.

## Улики

Файл из списка существует и непуст. Сборщики: `docs/drills/collect-server.sh` (хост), `docs/drills/collect-runner.ps1` (машина раннера).

- `chat.txt` — тексты по ролям, без ID и имён
- `job-list.txt` — список задач (сборщик хоста); `job-show-<N1>.txt`, `job-show-<N2>.txt`, `job-show-<N3>.txt`, `job-show-<N4>.txt` — подробности
- `server-journal.txt` — журнал `cs2-server` с метками времени (сборщик хоста)
- `runner.log`, `processes.txt` — журнал и процессы раннера
- `notes.txt`, `verdict.txt` — написаны руками
- `RESULT.md`, `token-scan.txt` — исполнитель

## Проверка

Команды исполнителя на машине автора (Git Bash, из корня репозитория):

```bash
bash docs/drills/evidence.sh import "$LOCALAPPDATA/cs2cinema/drills/raw/07-bot-live" .planning/phases/09-uborka-razvertyvanie-i-ucheniya/evidence/07-bot-live
bash docs/drills/evidence.sh check .planning/phases/09-uborka-razvertyvanie-i-ucheniya/evidence/07-bot-live --require-pass
```

Между ними исполнитель сверяет вердикт автора с фактами улик и пишет `RESULT.md` по формату README (`drill: 07-bot-live`, `result:` по уликам: `fail` при расхождении с вердиктом; `## Исход` — один абзац по шагам сценария; `## Улики` — список выше): в `chat.txt` есть ответы на все команды сценария; ни одной строки `бот→другу:` с локальным путём или кодом сбоя (`grep -nE '[A-Za-z]:\\|/var/|/home/|BAD_DEMO|TOO_MANY_GRANTS' chat.txt` по строкам `бот→другу:` пуст); отчёт `бот→автору:` с кодом `BAD_DEMO` есть; в `job-show-<N1>.txt` `sent`, в `job-show-<N4>.txt` `cancelled`.

Правило приёмки: учение пройдено только когда `bash docs/drills/evidence.sh check … --require-pass` для папки `07-bot-live` проходит. Код 1 при `import` — найден секрет: папку улик не коммитят, удаляют целиком, токен отзывают, учение повторяют. `result: fail` с полными уликами — записанный провал для `/gsd-plan-phase 9 --gaps`. Поиск токена по всем уликам, журналам, базам и чату (07-UAT тест 5) — отдельное учение `99-token-scan` плана 09-10.
