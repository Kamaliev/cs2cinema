# Учения: правила и инструменты

Учение — живая проверка цепочки бот, сервер, раннер на настоящих машинах: убить раннер посреди записи, перезапустить сервер посреди задачи, отправить демку в 500 МБ через прокси. Автоматические тесты (`runner --test chain`, `lease_http`, `remote::e2e`) проверяют те же механизмы на фейках; учение проверяет их на настоящих CS2, HLAE, systemd и сети.

Чем учение отличается от записи «со слов»: в v1.0 ручные проверки остались непроведёнными, а в `06-UAT.md` у «pass» нет папки `evidence/` (RESEARCH, Pitfall 8). Здесь результат учения — **папка улик**, которую проверяет скрипт. Нет папки, которая проходит проверку, — нет пройденного учения.

## Роли

| Роль | Что делает |
|------|------------|
| Исполнитель (агент) | собирает бинарники и репетирует на фейках; импортирует сырые папки в улики, ищет секреты, запускает `evidence.sh check`, пишет `RESULT.md` и сводки |
| Автор | действует у машин: разворачивает хост, убивает процессы, отправляет сообщения боту; запускает сборщики улик и копирует сырые папки на свою машину |

Исполнитель не проводит учения за автора и не «дописывает» то, чего не было. Автор не коммитит ничего в `evidence/`.

## Две папки на учение

| Папка | Где | Что в ней |
|-------|-----|-----------|
| сырая | вне репозитория: `%LOCALAPPDATA%\cs2cinema\drills\raw\NN-имя\` (в Git Bash `$LOCALAPPDATA/cs2cinema/drills/raw/NN-имя`) | всё как есть: копия базы сервера `raw-db\`, экспорт чата Telegram `chat-export\`, журналы, состояние раннера |
| улики | в репозитории: `.planning/phases/09-uborka-razvertyvanie-i-ucheniya/evidence/NN-имя/` | только отобранные текстовые файлы, `import-log.txt`, `token-scan.txt` и `RESULT.md` |

Репозиторий публичный. Поэтому в улики **не идут**: значения токенов и ключей, копии базы (`*.db`, `*.db-wal`, `*.db-shm`, `*.sqlite*`), экспорт чата Telegram, файл `token` раннера, Telegram-ID, имена друзей, файлы больше 5 МиБ. Пользователей стенда называют ролями: `автор`, `друг`, `незнакомец` — в сообщениях, в протоколах и в `RESULT.md`. Поиск секретов при этом идёт и по сырой папке: копия базы и экспорт чата проверяются, хотя в репозиторий не попадают.

Имена папок учений: `00-ci`, `00-deploy`, `00-spikes`, `00-live-chain`, `01-kill-runner`, `02-upload-cut`, `03-server-restart`, `04-cancel-offline`, `05-big-demo-proxy`, `06-version-mismatch`, `07-bot-live`, `08-day-soak`, `99-token-scan`.

## Файл образцов

Секреты, которые ищет `scan-token.sh`, лежат в одном файле, **вне репозитория**: `%LOCALAPPDATA%\cs2cinema\drills\patterns.txt` (или путь в переменной `CS2_DRILL_PATTERNS`). Одна строка — один секрет:

```
# токен тестового бота (с двоеточием)
<число>:<секретная часть>
# токен раннера
<токен раннера>
# ключ FACEIT
<ключ FACEIT>
```

Пустые строки и строки с `#` пропускаются, `CRLF` допускается. К каждой строке с `:` скрипт сам добавляет форму с `~` вместо первого `:` (так адрес с токеном маскируется в журналах) и секретную часть после `:`, если она не короче 16 знаков. Для тестового бота заведите отдельный токен: после учений его отзывают в `@BotFather`.

Скрипты **никогда не принимают секрет аргументом** (он виден в списке процессов и в истории shell) и **никогда не печатают найденное значение** — только имена файлов и числа совпавших строк. Файл образцов внутри рабочего дерева git `scan-token.sh` отвергает (код 2).

## Инструменты

Все команды исполнитель запускает в Git Bash из корня репозитория.

| Скрипт | Где работает | Что делает |
|--------|--------------|------------|
| `docs/drills/collect-server.sh` | Linux-хост, через `sudo` | собирает журналы сервера и bot-api, список задач, состояние служб, диск и копию базы в сырую папку |
| `docs/drills/collect-runner.ps1` | машина раннера, Windows PowerShell 5.1 | собирает `runner.log`, `runner_state.json`, листинг `out\` и `remote\`, процессы; токен раннера не копирует |
| `docs/drills/evidence.sh import <сырое> <улики>` | машина автора, Git Bash | отбирает текстовые файлы, пропуски пишет в `import-log.txt`, ищет секреты, пишет `token-scan.txt`; код 1, если секрет найден |
| `docs/drills/evidence.sh check <улики> [--require-pass]` | машина автора, Git Bash | проверяет `RESULT.md`, непустоту файлов из списка улик, отсутствие баз и чата, `token-scan.txt`, кодировку |
| `docs/drills/scan-token.sh <образцы> <путь>...` | машина автора, Git Bash | поиск секретов по произвольным путям (в текстах и в двоичных файлах) |
| `docs/drills/selftest.sh` | где угодно, Git Bash | самопроверка трёх скриптов на синтетике, последняя строка `selftest: OK` |

Порядок работы над одним учением:

1. Автор проводит учение по протоколу `docs/drills/NN-имя.md` (протоколы пишет план 09-07).
2. Автор запускает сборщики на хосте и на машине раннера и копирует результат в сырую папку `...\drills\raw\NN-имя\`.
3. Исполнитель: `bash docs/drills/evidence.sh import "$LOCALAPPDATA/cs2cinema/drills/raw/NN-имя" .planning/phases/09-uborka-razvertyvanie-i-ucheniya/evidence/NN-имя`.
4. Исполнитель пишет `RESULT.md` (формат ниже) со списком улик.
5. Исполнитель: `bash docs/drills/evidence.sh check .planning/phases/09-uborka-razvertyvanie-i-ucheniya/evidence/NN-имя --require-pass`.
6. Только после этого папку улик коммитят.

## Формат `RESULT.md`

Первые три строки — служебные, дальше два раздела:

```markdown
drill: 01-kill-runner
result: pass
date: 2026-10-20

## Исход

Один абзац: что произошло, чем закончилось, какие сообщения увидел друг. Роли вместо имён.

## Улики

- server-journal.txt — журнал cs2-server за время учения
- runner.log — журнал раннера
- job-show-12.txt — служебная команда `job show 12`
```

`drill:` совпадает с именем папки, `result:` равен `pass` или `fail`, дата вида `ГГГГ-ММ-ДД`. Каждый файл из списка существует и непуст. Строка списка: `- <файл> — <что это>` (длинное тире).

## Правило кодировки

Все файлы улик — в UTF-8. `grep -F` не найдёт токен в файле в UTF-16, а Windows PowerShell 5.1 пишет UTF-16 при перенаправлении `>` и в `Tee-Object`. Поэтому в PowerShell вывод в файл улик — только так:

```powershell
<команда> | Out-File -Encoding utf8 <файл>
```

Не `>`, не `>>`, не `Tee-Object`. `evidence.sh check` отвергает файлы, которые начинаются байтами `FF FE` или `FE FF`: «файл в UTF-16, пересохраните в UTF-8». `collect-runner.ps1` сам пишет только в UTF-8. Файлы, правленные вручную, сохраняйте как UTF-8 (с меткой или без).

## Образец протокола

Каждый протокол `docs/drills/NN-имя.md` имеет семь разделов в таком порядке (по нему план 09-07 пишет протоколы):

```markdown
# NN-имя: название учения

## Цель
Что проверяем и какой критерий или вопрос из 07-UAT / 08-UAT закрываем.

## Предусловия
Машины, версии, готовые файлы, файл образцов, чистые сырая папка и папка улик.

## Шаги
Нумерованные команды, кто их выполняет (автор или исполнитель), что именно нажать или набрать.

## Ожидаемый исход
Продолжение работы или понятное сообщение на русском, без локальных путей. Что увидит друг в чате.

## Чего быть не должно
Две одновременные записи, два ролика в чате, потерянный результат, секрет в журнале, зависшая задача.

## Улики
Список файлов для `RESULT.md` и команды их сбора (`collect-server.sh`, `collect-runner.ps1`).

## Проверка
Команды исполнителя: `bash docs/drills/evidence.sh import …`, `bash docs/drills/evidence.sh check … --require-pass`.
```

## Правило приёмки

**Учение засчитывается пройденным только когда папка его улик проходит `evidence.sh check <папка> --require-pass`.**

Обычный `check` (без флага) подтверждает полноту улик и отсутствие секретов и пропускает записанный провал: `result: fail` с полными уликами — это **записанный провал**, а не пройденное учение. В сводке он считается провалом.

## Правило повтора

Прерванное или повторное учение проходят заново с чистого листа: **удалить сырую папку и папку улик целиком** и провести учение сначала. Два прогона в одну папку не сливаются: `import` перезаписывает файлы с теми же именами, но не удаляет лишние файлы прошлого прогона, и в уликах окажется смесь. Два `import` в одну папку одновременно не запускают.

Если `import` нашёл секрет (код 1): папку улик не коммитят, удаляют целиком; источник утечки устраняют (например, понижают `TELEGRAM_VERBOSITY` у bot-api), токен отзывают, учение повторяют.

## Репетиция на фейках перед живыми учениями

Перед учениями исполнитель прогоняет автоматические проверки тех же механизмов; зелёная репетиция не заменяет учение, но отсекает ошибки сборки:

```
cargo test --release -p runner --test chain
cargo test --release -p runner --test outbox
cargo test --release -p runner --test sweep
cargo test --release -p server --test lease_http
cargo test --release -p server --test cleanup
cargo test --release -p app --bin cs2cinema remote::e2e
bash docs/drills/selftest.sh
```

## Что делать при провале

1. Не «чинить на ходу»: записать `result: fail` в `RESULT.md` с полными уликами (что случилось, что увидел друг, где остановилось).
2. Пройти `import` и обычный `check`: провал тоже должен быть записан проверяемо.
3. Дальше — `/gsd-plan-phase 9 --gaps`: исправление выделяется в отдельный план, после него учение проходят заново (правило повтора).
